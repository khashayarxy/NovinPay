# NovinPay

وب‌سایت رسمی **NovinPay**؛ کسب‌وکار فروش و تعمیر دستگاه‌های کارتخوان (POS) در شهریار. این نسخه شامل وب‌سایت عمومی فارسی RTL، ثبت و پیگیری خصوصی درخواست آنلاین تعمیر و پایهٔ مدیریت کسب‌وکار با مدیر کل محافظت‌شده و مجوزهای صریح کارکنان است.

## فناوری‌ها

- Laravel 13 با PHP 8.4.1 یا بالاتر (مطابق وابستگی‌های قفل‌شده)
- Blade + HTML/CSS/JavaScript
- Tailwind CSS v4 (از طریق Vite) — از قبل در اسکلت پروژه پیکربندی شده است
- PHPUnit
- پایگاه دادهٔ توسعه: SQLite — پایگاه دادهٔ تولید پیشنهادی: MySQL/MariaDB

## راه‌اندازی

```bash
composer install
cp .env.example .env        # در صورت نیاز
php artisan key:generate
touch database/database.sqlite
php artisan migrate
php artisan test             # اجرای تست‌ها
npm install
npm run build               # یا npm run dev برای توسعه
php artisan serve
```

## پنل مدیریت

از فاز ۵، Gate با نام `access-admin` فقط مجوز فعال ذخیره‌شده در `admin_accounts` را می‌پذیرد؛ تطابق ایمیل به‌تنهایی دسترسی نمی‌دهد. مدیر کل تنها حساب محافظت‌شده است و کارکنان دسترسی پیش‌فرض ندارند. ارتقای نصب موجود باید در حالت نگهداری و طبق [راهنمای فاز ۵](docs/PHASE5.md) انجام شود؛ اجرای migration به‌تنهایی مدیر ایجاد نمی‌کند.

- آدرس ورود: `/admin/login` — ثبت‌نام عمومی وجود ندارد. مدیر کل کارکنان را با مجوزهای مشخص و گذرواژهٔ موقت تعریف می‌کند؛ تغییر گذرواژه در اولین ورود اجباری است.
- روی نصب موجود Seeder اجرا نکنید. پس از تأیید جداگانهٔ استقرار، پشتیبان‌گیری و migration، شناسهٔ حساب فعلی مالک را بررسی و سپس همان حساب را مجاز کنید:

```bash
php artisan admin:bootstrap VERIFIED_EXISTING_USER_ID
php artisan admin:bootstrap VERIFIED_EXISTING_USER_ID --apply
```

- امکانات: پیشخوان با آمار واقعی، مدیریت همکاران، تاریخچهٔ فعالیت، نمای فقط‌خواندنی درخواست آنلاین تعمیر و مدیریت محصولات. مشاهدهٔ اطلاعات مشتری مجوز جداگانه دارد؛ درخواست آنلاین به معنی دریافت فیزیکی دستگاه نیست.
- مدیریت محصولات شامل انتشار/پیش‌نویس، مشخصات فنی و بارگذاری تصویر JPEG/PNG/WebP تا ۲ مگابایت است. مشاهده و تغییر محصول مجوزهای جداگانه دارند.
- مسیرهای مدیریت پشت احراز هویت، اعتبارسنجی نسخهٔ نشست و Gate/Policy هستند. تغییر مجوز، غیرفعال‌سازی یا بازنشانی گذرواژه نشست‌های قبلی کارمند را باطل می‌کند. لاگین محدودیت نرخ قبلی (۵ تلاش برای ایمیل و ۳۰ تلاش برای IP در دقیقه) را حفظ می‌کند.
- `ADMIN_EMAIL` فقط برای تطبیق هویت در فرمان bootstrap و ساخت اولیه استفاده می‌شود. Seeder حساب موجود را تغییر نمی‌دهد و مجوز مدیریت اعطا نمی‌کند. ایمیل و گذرواژهٔ حساب فعلی در bootstrap حفظ می‌شوند.
- تصاویر روی دیسک `public` و در `storage/app/public/products/` ذخیره می‌شوند (در گیت نادیده گرفته می‌شوند)؛ در محیط توسعه `php artisan storage:link` لازم است. راهنمای کامل استقرار در `docs/DEPLOYMENT.md` است.

## داده‌های نمونه

کاتالوگ روی یک نصب تازه **خالی** است و حالت «هنوز محصولی ثبت نشده است» را نمایش می‌دهد. برای مشاهدهٔ کارت محصولات در محیط توسعه:

```bash
php artisan db:seed --class=SampleProductSeeder
```

تمامی رکوردهای این Seeder با `is_sample = true` ثبت می‌شوند و در رابط کاربری با نشان «داده نمونه» نمایش داده می‌شوند. این Seeder عمداً در `DatabaseSeeder` فراخوانی نمی‌شود.

## پایگاه داده

- **توسعه (موقت):** SQLite (`database/database.sqlite`) — در محیط فعلی سرور MySQL/MariaDB در دسترس نیست.
- **تولید (هدف):** MySQL یا MariaDB. پیش از استقرار باید `DB_CONNECTION` و اعتبارنامه‌های دیتابیس در `.env` تنظیم شوند.
- سازگاری با MySQL واقعی **آزموده شد** (MySQL 8.0.46 با `utf8mb4_unicode_ci`): همهٔ migrationها (شامل backfill جستجو) و کل ۱۲۳ تست (۴۶۱ assertion) روی MySQL سبز بودند. ستون JSON برای `specifications`، ایندکس یکتای `slug`، ستون `boolean` با مقدار پیش‌فرض و `like` در جستجو همگی سازگارند.
- **جستجو نرمال‌سازی می‌شود:** ارقام فارسی/عربی به ASCII، حروف `ي/ك` به `ی/ک`، حذف نیم‌فاصلهٔ مخفی (ZWNJ) و فشردن فاصله‌های تکراری انجام می‌شود تا جستجو با هر variant کارا باشد؛ کاراکترهای `%`/`_` نیز در ورودی کاربر به‌صورت تحت‌اللفظی match می‌شوند (wildcard نیستند). در ستون مشتق `search_text` ذخیره می‌شود و متن نمایشی دست نمی‌خورد.

هیچ `.env` واقعی نباید متعهد (commit) شود؛ فقط `.env.example` بدون رمز عبور.

## تصمیم‌های باز (نیازمند تأیید)

- نام دامنه و آدرس نهایی وب‌سایت
- آدرس مخزن Git و ریموت
- متن نهایی شرایط استفاده و حریم خصوصی
- انتخاب ایمیل/گذواژهٔ نهایی مدیر و محل نگهداری آن

لوگوی رسمی و فاوآیکون‌های اصلی در `public/`، رنگ برند `#098CF7` در توکن‌های CSS و اطلاعات تأییدشدهٔ کسب‌وکار در `config/business.php` یکپارچه شده‌اند. ایمیل عمومی یا شبکهٔ اجتماعی تأییدنشده اضافه نشده است. در ویندوز برای اجرای تست‌های ایزوله با PHP موجود در PATH یا Herd از `./scripts/test.ps1` استفاده کنید؛ تنظیمات سیستم تغییر نمی‌کند.

## فازهای بعدی (خارج از محدودهٔ این نسخه)

سبد خرید و پرداخت، مدیریت موجودی پیشرفته، چرخهٔ کامل مدیریت تعمیر، پیامک و استقرار تولید.

فاز ۴ صفحات عمومی را با ظاهر تأییدشدهٔ صفحهٔ اصلی هماهنگ می‌کند و پایهٔ ثبت و پیگیری درخواست آنلاین تعمیر را اضافه می‌کند. migration جدید فقط جدول `repair_requests` را می‌سازد؛ روی دیتابیس اصلی موجود اجرا نشده است. محدودیت‌ها، تصمیم‌های باز مالک و نتایج بررسی در [docs/PHASE4.md](docs/PHASE4.md) آمده است. این فاز شامل پذیرش فیزیکی دستگاه یا پنل مدیریت تعمیرات نیست.
